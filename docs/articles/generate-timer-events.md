## Generate Timer Events

Besides the [heartbeat](./set-clock.md) event, the Timestamp Generator Gen3 can also broadcast a high frequency (50 - 1000 Hz) counter using the [`Timer`] register. Each counter event carries an incrementing value timestamped with the device's clock.

The [`Timer`] counter is useful for inspecting the device's clock and detecting dropped messages. It can also be used to assign Harp timestamps to data that are not generated by Harp devices, such as software-generated events, thereby placing them on the same timeline.

This article covers how to enable the counter event, observe the events in Bonsai, set the counter value, and assign Harp timestamps to software events.

The complete workflow is shown below:

:::workflow
![Generate Timer Events Top Level](../workflows/generatetimerevents-toplevel.bonsai)
:::

> [!WARNING]
> For the rest of these workflows, use the device-specific versions of these operators, e.g. `Device (Harp.TimestampGeneratorGen3)` instead of `Device (Harp)`. If correctly selected, the names of these operators in the workflow panel will change to reflect either the name of the device or the selected register/payload.

### Enable Timer Events

The counter is disabled by default, so the [`TimerFrequency`] register must be enabled before any events are produced.

:::workflow
![Enable Timer Events](../workflows/generatetimerevents-frequency.bonsai)
:::

- Insert a [`KeyDown`] operator and set the `Filter` property to `A`.
- Insert a [`CreateMessage`] operator and configure the following properties:
    - `Payload` - Set to `TimerFrequency`.
    - `TimerFrequency` - Set the desired frequency (e.g  `Timer50Hz` to generate 50 events per second).
- Insert a [`MulticastSubject`] operator named `TimestampGeneratorGen3 Commands`.

### Observe Timer Events

Each [`Timer`] event carries the current counter value and the timestamp at which it was generated. To display those events, we will subscribe to the device events and parse the [`Timer`] messages.

:::workflow
![Observe Timer Events](../workflows/generatetimerevents-events.bonsai)
:::

- Insert a [`SubscribeSubject`] operator named `TimestampGeneratorGen3 Events`.
- Insert a [`Parse`] operator and set the `Register` property to `TimestampedTimer`.
- Insert a [`VisualizerWindow`] operator. This will automatically open a visualizer displaying the parsed events when the workflow starts.

Run the workflow and press <kbd>A</kbd> to enable the counter. 

The visualizer will start streaming events, similar to the following:

```text
4778@95.563344
4779@95.583344
```

The first number corresponds to the counter, and the second number is the timestamp on the device clock.

### Set Counter Value

Writing to the [`Timer`] register sets the value of the counter. This is useful for resetting the counter to zero at the start of a session.

:::workflow
![Set Counter Value](../workflows/generatetimerevents-counter.bonsai)
:::

- Insert a [`KeyDown`] operator and set the `Filter` property to `S`.
- Insert a [`CreateMessage`] operator and configure the following properties:
    - `Payload` - Set to `Timer`.
    - `Timer` - Set to 0 to reset the counter.
- Insert a [`MulticastSubject`] operator named `TimestampGeneratorGen3 Commands`.

Run the workflow and press <kbd>S</kbd>. The counter value in the visualizer window will reset to zero.

> [!TIP]
> To reset the onboard clock that timestamps the events, see the [Set Clock](set-clock.md) article.

### Timestamp Software Events

Software events, such as key presses, can be assigned Harp timestamps by pairing them with the latest [`Timer`] event.

:::workflow
![Timestamp Software Events](../workflows/generatetimerevents-softwareevents.bonsai)
:::

- Insert a [`KeyDown`] operator and set the `Filter` property to `D`. This is the software event that will be timestamped.
- Insert a [`WithLatestFrom`] operator.

In a separate branch:

- Insert a [`SubscribeSubject`] operator named `TimestampGeneratorGen3 Events`.
- Insert a [`Parse`] operator and set the `Register` property to `TimestampedTimer`.

To combine the two branches:

- Connect the [`Parse`] operator to the [`WithLatestFrom`]. Each key press will now be paired with the latest [`Timer`] event.
- Insert a [`VisualizerWindow`] operator to display the paired events.

Run the workflow, and then press <kbd>D</kbd>. Each key press will appear in the visualizer window paired with the latest timestamped counter value, like this:

```text
(D, 141404@19990.36)
(D, 146440@20000.66)
```

> [!NOTE]
> The timestamp resolution with this strategy is set by the [`TimerFrequency`] (e.g. 20 ms at 50 Hz). Use a higher frequency for finer resolution. Keep in mind, however, that Windows is a non real-time operating system and software timestamping is not ideal for high-precision timing applications.
